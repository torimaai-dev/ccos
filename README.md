# Captain Chappy（CC）

**AIとの対話に、操縦席と外部記憶を持たせる。**

Captain Chappy（CC）は、ChatGPT / Codex / AIエージェントとの対話を、その場限りの会話で終わらせず、継続的に使える作業環境へ変えるための実験的なOSSプロジェクトです。

単なるプロンプト集ではありません。

CCは、ユーザーの目的、制約、判断軸、過去の合意、作業ルール、未決事項をGitHub上の外部記憶として整理し、AIとの次の対話・作業・レビューに引き継ぐための **AIコックピット／対話ハーネス／記憶管理レイヤー** です。

目指しているのは、AIに人間の判断を任せることではありません。  
人間が自分の意図と判断権を保ったまま、AIを継続的な相棒として使える状態を作ることです。

---

## このプロジェクト自体が実験です

Captain Chappyは、ノンプログラマーがChatGPTとの対話を通じて作り上げている実験的なOSSプロジェクトです。

このリポジトリは、単に「AIを便利に使うための説明書」ではありません。

ユーザーがAIと対話しながら、自分専用の外部記憶、作業ルール、プロンプト、ワークフロー、Codexへの引き継ぎ形式を整え、実際にAI活用環境を育てていく過程そのものを示しています。

つまりCaptain Chappyは、次のことを実証しようとしています。

- ノンプログラマーでも、AIとの対話を通じて自分用のAI運用環境を作れる
- GitHubを使えば、AIの記憶や判断軸を見える形で保存・改善できる
- ChatGPTやCodexは、コードを書くためだけでなく、ユーザーの思考・作業・記憶を整理する相棒として使える
- AIとの会話は、その場限りで消えるものではなく、次の作業に引き継げる資産にできる

Captain Chappyを作ること自体が、Captain Chappyの使い方のデモになっています。

---

## なぜ作るのか

ChatGPTやCodexはすでに強力です。

しかし、AIとの対話が長くなるほど、次のような問題が起きます。

- 最初の目的が途中で薄れる
- 何が決定済みで、何が仮置きか曖昧になる
- 過去の合意や禁止事項が次の会話に引き継がれない
- ユーザーの好み、違和感、判断軸が毎回リセットされる
- AIが良かれと思って、未承認の判断を混ぜてしまう
- セッションが変わると、また文脈を説明し直す必要がある

これは、モデル性能だけの問題ではありません。

**AIとの対話には、継続するための記憶と、判断を支える操縦席が必要です。**

Captain Chappyは、そのための作業環境をGitHub上に作る試みです。

## Captain Chappyで作れるもの

Captain Chappyを使うと、ユーザーは自分専用のAI作業環境を作れます。

たとえば、次のようなものです。

- ChatGPTに読ませる自分用の取扱説明書
- GitHub上に置く外部記憶ファイル
- 会話から重要な文脈を回収するメモ
- Codexに渡す作業指示
- プロンプトやワークフローの更新ルール
- 未決事項や反映候補を整理する仕組み
- 次の相談や作業に引き継ぐためのメモ
- AIが参照できる判断軸や作業ルール
- 対話を次回に引き継ぐためのワークフロー

これは、プログラマーだけのものではありません。

AIとの対話を通じて、自分の思考、判断軸、作業ルールを少しずつ外部化し、AIが使える形に整えていくための仕組みです。

---

## 目指しているもの

Captain Chappyが目指すのは、誰もが自分専用のAI記憶を持てる状態です。

ChatGPTの一時的な会話履歴や、見えにくい記憶だけに頼るのではなく、GitHub上にユーザー自身が確認・編集・レビューできる外部記憶を作ります。

そこには、たとえば次のようなものを置きます。

- ユーザーの判断軸
- 作業ルール
- 会話から回収した重要メモ
- ワークフロー
- ナレッジ
- プロンプト
- AGENTS.md
- Codexへの引き継ぎ指示
- レビュー手順
- 未決事項や反映候補

GitHubをAIの外部記憶にすることで、記憶は次の性質を持てます。

- 見える
- 編集できる
- バージョン管理できる
- レビューできる
- 共有できる
- 再利用できる
- 必要なら戻せる

AIとの対話が、その場限りの会話ではなく、積み上がる作業環境になります。

## AIとの対話は、なぜこれで強くなるのか

AIが本当に役立つには、単発で賢い回答をするだけでは足りません。

ユーザーが何を大事にしているか。  
何を嫌がるか。  
どこまで進めてよいか。  
何をまだ決めていないか。  
次に何を確認すべきか。

こうした文脈を扱えるほど、AIは「便利な返答者」から「継続して相談できる相棒」に近づきます。

Captain Chappyは、そのために次の補助レイヤーを作ります。

### 1. 意図を失わない

ユーザーの目的、制約、好み、違和感、判断基準を外部記憶として保持します。

AIが毎回ゼロから推測するのではなく、ユーザーの文脈に沿って対話しやすくなります。

### 2. 状態を取り違えない

「相談中」「仮置き」「採用済み」「未確認」「反映待ち」を分けて扱います。

これにより、AIが未承認の内容を正式なルールとして扱う事故を減らします。

### 3. 会話を次に引き継げる

雑な相談、壁打ち、作業ログを、次に使えるメモやタスクに変換します。

会話が消費されるのではなく、次の対話や作業の材料になります。

### 4. 記憶をメンテナンスできる

蓄積されたメモやルールは、そのままだと古くなり、重複し、矛盾します。

CCは、AIが外部記憶を読み、整理し、次に使いやすい形へ整えることを目指します。

人間の脳が睡眠中に記憶を整理するように、AIとの作業記憶も定期的に整える必要があります。

### 5. 次の一手を提案できる

CCは、保存された文脈を読むことで、ユーザーがまだ明確に質問できていない段階でも、次に必要な確認点や作業を提案します。

これはAIが勝手に決めるという意味ではありません。

人間の判断権を残したまま、次の問い・作業・レビュー観点を見つけるためのプッシュ型ガイドです。

## Captain の意味

Captain Chappyの “Captain” は、AIが人間の代わりに船長になるという意味ではありません。

むしろ逆です。

AIが勝手に進むのではなく、人間が目的地と判断権を保ったまま、AIを乗りこなすための操縦席を作る。

それがCaptain Chappyです。

CCは、AIにすべてを任せるための仕組みではありません。

**人間とAIが同じ文脈を見ながら進むための、コックピットであり、ナビゲーターであり、記憶管理システムです。**

## 主なユースケース

Captain Chappyは、次のような用途を想定しています。

- ChatGPTとの継続対話の文脈管理
- GitHubを使ったAI外部記憶の構築
- 会話ログから再利用できるナレッジを抽出
- メモと正式ルールの分離
- プロンプトやワークフローのメンテナンス
- Codexに渡す作業指示の整理
- AGENTS.mdの設計
- 非エンジニア向けのAI活用環境づくり
- note / X / コンテンツ制作のワークフロー化
- 次に必要な確認点・作業・レビュー観点の提案

---

## これは何ではないか

Captain Chappyは、次のようなものではありません。

- 汎用プロンプト集
- AIに全部任せる自動化ツール
- 完成済みのエージェントフレームワーク
- 人間の判断を置き換える仕組み
- 見えないところで勝手に記憶を書き換える仕組み

CCが重視するのは、ユーザーが確認できること、レビューできること、必要なら戻せることです。

AIを強くするために、人間の判断を隠すのではなく、むしろ見える形にします。

## 長期ビジョン

AIが強くなるほど、必要になるのはモデルだけではありません。

ユーザーごとの意図、記憶、判断軸、作業ルールを扱うための標準的なレイヤーが必要になります。

Captain Chappyは、そのレイヤーを小さく実験するプロジェクトです。

最終的に目指しているのは、次の状態です。

**誰もが、自分で所有でき、見直せて、育てられるAI記憶を持ち、ChatGPTやCodexを自分の文脈で使えること。**

そして、AIが単発の回答者ではなく、継続的に相談できる相棒として機能することです。
