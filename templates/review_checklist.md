# Review Checklist Template

このチェックリストは、Captain Chappy（CCOS）で作成・更新したファイルを確認するためのものです。

## 1. Purpose

- [ ] このファイルの目的は明確か
- [ ] README、docs、templates、examples のどこに置くべきか合っているか
- [ ] 既存ファイルと役割が重複していないか

## 2. Public safety

- [ ] 公開してよい内容だけになっているか
- [ ] 個人情報や固有の非公開事情が入っていないか
- [ ] 実例は一般化・匿名化されているか

## 3. Concept alignment

- [ ] 「AIとの対話に、操縦席と外部記憶を持たせる」という中核からズレていないか
- [ ] 単なるプロンプト集として見えすぎていないか
- [ ] AIに全部任せる自動化として誤解されないか
- [ ] 人間の判断権が残る説明になっているか

## 4. State handling

- [ ] 下書き、反映候補、採用済みが混ざっていないか
- [ ] 未確認の内容を確定扱いしていないか
- [ ] 次に確認すべきことが明確か

## 5. Readability

- [ ] 非エンジニアにも読めるか
- [ ] 抽象語だけで終わっていないか
- [ ] 長すぎる説明はdocsへ分けられているか
- [ ] READMEは入口として読みやすいか

## 6. Maintenance

- [ ] 将来更新しやすい構成か
- [ ] テンプレート化できる部分はtemplatesへ分けられているか
- [ ] 実例化できる部分はexamplesへ分けられているか
- [ ] AGENTS.mdに反映すべき作業ルールがないか

## 7. Final check

- [ ] この変更でCCOSの理解は進むか
- [ ] 余計な複雑さを増やしていないか
- [ ] 公開リポジトリとして見られて問題ないか
