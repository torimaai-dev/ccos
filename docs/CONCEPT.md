# Captain Chappy Concept

## 一言でいうと

Captain Chappy（CCOS）は、AIとの対話に「操縦席」と「外部記憶」を持たせるための実験です。

ChatGPTやCodexを、その場限りの回答者ではなく、継続的に相談できる相棒として使うために、ユーザーの意図、制約、判断軸、過去の合意、作業ルールを見える形で整理します。

## 背景

AIはすでに強力です。

しかし、長い対話や継続プロジェクトでは、モデルの性能だけでは解けない問題があります。

- 最初の目的が途中で薄れる
- ユーザーの判断軸が毎回リセットされる
- 未確認の内容が確定扱いされる
- 仮置きメモと正式ルールが混ざる
- セッションが変わると文脈を説明し直す必要がある
- AIが良かれと思って未承認の補完をしてしまう

これは、AIとの対話に「継続するための作業環境」が足りない問題です。

## 3つの中核

### 1. AI Cockpit

AIを丸投げ先として扱うのではなく、人間が意図と判断権を保ったまま使うための操縦席です。

ここでいう操縦席とは、次のようなものです。

- 何を目的にしているか
- 何を守るべきか
- どこまでAIが進めてよいか
- 何を勝手に変えてはいけないか
- どこで人間の確認が必要か

AIが強くなるほど、こうした操縦席の重要性は増します。

### 2. GitHub as AI Memory

CCOSでは、GitHubをAIの外部記憶として扱います。

会話履歴や見えにくい記憶だけに頼るのではなく、ユーザー自身が確認・編集・レビューできるファイルとして文脈を保存します。

GitHub上の記憶は、次の性質を持てます。

- 見える
- 編集できる
- バージョン管理できる
- レビューできる
- 共有できる
- 必要なら戻せる

AIの記憶を、ユーザーが所有し、見直し、育てられる形にすることが重要です。

### 3. Push-Type Guidance

通常のAIアシスタントは、ユーザーが明確な質問をするまで待ちます。

しかし実際の作業では、ユーザー自身も「次に何を聞けばいいか」「どこから再開すればいいか」が曖昧なことがあります。

CCOSは、保存された文脈を読み、次に必要になりそうなことを提案するプッシュ型のガイドを目指します。

たとえば、次のような支援です。

- 次に確認すべきことを出す
- 未決事項を見つける
- 古いメモや重複を整理する
- Codexに渡す作業単位を作る
- 次回の対話に必要な引き継ぎメモを作る

これはAIが勝手に決めるという意味ではありません。

人間の判断権を残したまま、次に進みやすくするための補助です。

## このプロジェクト自体がデモである

Captain Chappyは、ノンプログラマーがChatGPTとの対話を通じて作っている実験的なOSSです。

つまり、このリポジトリ自体が次の実証です。

- ノンプログラマーでも、AIとの対話で自分用のAI運用環境を作れる
- GitHubを使えば、AIの記憶や判断軸を見える形にできる
- CodexやChatGPTは、コードだけでなく、思考・作業・記憶の整理にも使える
- AIとの会話は、その場限りではなく、次の作業に引き継げる資産にできる

Captain Chappyを作ること自体が、Captain Chappyの使い方のデモになっています。

## 睡眠中の記憶整理という比喩

記憶は、保存するだけでは使いにくくなります。

人間の脳が睡眠中に記憶を整理するように、AIとの会話や作業ログも、定期的に整理する必要があります。

- 重複を減らす
- 古い情報を見つける
- 仮置きと採用済みを分ける
- 次回使いやすい形にする
- 必要な文脈だけを取り出しやすくする

CCOSは、AIとの作業記憶をメンテナンスする仕組みを作ろうとしています。

## 長期ビジョン

AIが強くなるほど、必要になるのはモデルだけではありません。

ユーザーごとの意図、記憶、判断軸、作業ルールを扱うための標準的なレイヤーが必要になります。

Captain Chappyは、そのレイヤーを小さく実験するプロジェクトです。

最終的に目指しているのは、誰もが、自分で所有でき、見直せて、育てられるAI記憶を持ち、ChatGPTやCodexを自分の文脈で使えることです。
